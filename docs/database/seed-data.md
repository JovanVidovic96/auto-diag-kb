# Seed data

All data is entered by hand into JSON files. Nothing is generated by a script. Sources are generic OBD-II code definitions, manufacturer engine specifications, typical repair practice and real service reports.

## Files

```text
data/seed/
├── manufacturers.json
├── models.json
├── engines.json
├── components.json
├── dtc_codes.json
├── symptoms.json
├── causes.json
├── solutions.json
├── workshops.json
├── users.json
├── vehicles.json
├── service_records.json
└── edges/
    ├── has_model.json
    ├── ...
    └── replaced.json
```

One file per collection, a JSON array of documents. Edge files use keys from the other files:

```json
[
  { "_from": "dtc_codes/P0420", "_to": "causes/worn-catalytic-converter", "probability": 0.6 },
  { "_from": "dtc_codes/P0420", "_to": "causes/faulty-rear-o2-sensor", "probability": 0.3 }
]
```

## Privacy of service reports

Service reports contain personal data. Before they go into the repository:

- VIN: the first 11 characters are kept (maker, model attributes, model year, plant), the last 6 (serial number) are replaced with a running number.
- Registration plates are replaced with made-up plates in the same format.
- Owner names are invented. Owners in `users.json` are fictional people.
- Workshop names and addresses may stay if the workshop is a public business; otherwise they are replaced too.

## Loader

`python -m app.db.seed`:

1. Runs `schema.py`, so collections, graphs, indexes and the view exist.
2. Validates every record with its Pydantic model. Invalid files stop the import with the file name and row number.
3. Checks that every `_from` and `_to` points to an existing document.
4. Checks graph rules: `caused_by` probabilities per code at most 1, one open `owns` per vehicle, one `works_at` per mechanic, service mileage not decreasing per vehicle.
5. Hashes `SEED_USER_PASSWORD` for seeded users and creates the admin from `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
6. Computes `parts_rsd` and `total_rsd` from the `replaced` edges and sets each vehicle's `mileage_km` to its latest record.
7. Imports with `import_bulk(..., on_duplicate="replace")`.
